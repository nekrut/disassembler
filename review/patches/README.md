# Proposed patches

Fix proposals collected from the review, one file per finding or group of findings, named after the finding ids. They are proposals for the maintainers to review, not merged changes. Patches for this repository are in this directory and apply to commit 25c27f2; patches for the Galaxy wrappers of tools-iuc PR #8800 are in [`tools-iuc-pr8800/`](tools-iuc-pr8800/README.md). The two tables below cover the walker and everything else.

---

## Walker fix proposals

These are proposals for the maintainers to review, not merged changes: none of them is on any branch, and each was written and tested against a scratch copy of `walker/` at 25c27f2 during verification.

How to use them:

- Every patch is rooted at the repository root (`walker/...`) and applies on its own to 25c27f2 with `git apply` (checked with `git apply --check` against a clean clone). Only the path headers were rewritten; the hunks are the verifier's. One exception, noted in its row: the WV-09 patch was written as a normal (non-unified) diff and was converted to unified form; the result is byte-identical to the verifier's patched file.
- "Tested" reports what the verifier ran on their patched copy. Nothing was rebuilt for this collection. Where a row says "N unit + M CLI", that is `cargo test --release -- --skip empty_subgraph_yields_nothing` on the patched copy.
- "Does not apply on top of" comes from applying every pair of patches that touch a common file, one after the other, to a clean tree. Most of these are overlapping hunks in the same function or at the end of the same test module, and need a rebase rather than a design decision. Pairs with a real design overlap are spelled out in the Notes.
- File paths in the third column are under `walker/`.

## Python, tests, docs and packaging fix proposals

These are proposals for the maintainers to review, not merged changes: none of them is on any branch. Each was written while a finding was being verified, and was re-checked here against a clean clone of 25c27f2.

How to use them:

- Every patch except `PM-02-...` is rooted at the repository root and applies on its own to 25c27f2 with `git apply` (checked with `git apply --check` on a clean clone). Only the path headers were rewritten; the hunks are the ones written during verification. Each patch carries `index` lines naming the 25c27f2 blobs, so `git apply --3way` can merge it onto a tree that already has another patch.
- `PM-02-sieve-lsh-table-grows.patch` is for the sieve submodule. Apply it inside the submodule (`git -C extern/kmer-diversity-sieve apply PM-02-sieve-lsh-table-grows.patch`) at the pinned commit 39d90c0. It belongs upstream in kmer-diversity-sieve, followed by a submodule bump here.
